## 3. Анализ непокрытых участков

Непокрытые строки не влияют на достижение целевого порога и объясняются
инфраструктурными ветками, не задействованными в тестовой среде:

- **`config/database.js` (ветка PostgreSQL и файловый SQLite)** — в тестах
  используется исключительно in-memory SQLite, поэтому ветвь подключения к
  PostgreSQL и создание директории для файловой БД не исполняются. Это ожидаемо:
  тестировать реальное подключение к внешней СУБД в unit/integration-наборе
  нецелесообразно.
- **`app.js` (ветки логирования morgan и обработка отсутствия модуля auth)** —
  логирование отключено в `NODE_ENV=test`; модуль auth в тестовой сборке
  присутствует, поэтому ветка «модуль не подключён» не исполняется.
- **`controllers/*` (ветки `catch (err) → next(err)`)** — блоки обработки
  непредвиденных исключений БД. Их срабатывание требует искусственного слома
  драйвера БД; поведение `errorHandler` при этом покрыто отдельными unit-тестами.

## 4. Выявленные проблемы

В ходе разработки тестов подтверждены следующие особенности поведения (не дефекты,
но зафиксированы во избежание регрессий):

| # | Наблюдение | Решение |
| - | ---------- | ------- |
| 1 | На только что созданной задаче поле `completedAt` имеет значение `undefined`, а не `null`. | Тесты используют нестрогую проверку `== null`, допускающую оба значения. |
| 2 | SQLite не обеспечивает соблюдение ограничения `ENUM` на уровне БД — недопустимый `priority`/`status` не отклоняется моделью. | Валидация недопустимых значений выполняется на уровне контроллера (`validatePriorityAndStatus`) и покрыта интеграционными тестами. |
| 3 | Jest сообщал о незакрытых асинхронных хендлах после прогона. | Соединение с БД закрывается в `afterAll` (`sequelize.close()`); для стабильного завершения набора используется корректное закрытие в каждом интеграционном файле. |

Дефектов в продуктовом коде, требующих исправления, **не выявлено** — все
функциональные требования (FR-1…FR-4) подтверждены тестами.
